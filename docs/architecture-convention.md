## The convention

1. **One lifecycle entry.** `src/index.ts` holds `construct`, `start` and `stop` and the published exports. Every other entry (a bin, `dmsFrontend`, a test harness) is named in `package.json`, never discovered.
2. **One folder per domain under `src/`, ranked.** Each folder has an `index.ts` as its only entry, an `internal.ts` where sibling tiers need more, and a rank in the dependency-cruiser config. A folder the config does not rank fails `pnpm run deps`. Imports go only downward. The three repositories spell the rank three ways; the convention asks for the same three rule names everywhere, `<module>-entry-only`, `<module>-no-upward` and `unranked-folder`, so `antelopejs-sync`'s entry-only check and a reviewer read every config the same way.
3. **Tests mirror `src/`.** A unit test lives at `src/test/unit/<path>.test.ts` or `test/<path>.test.ts` for `src/<path>.ts`. Integration tests live in one folder behind one harness that `antelopeJs.test` names. `AGENTS.md` has one `## Tests` section with the command per tier, which the verify skill reads.
4. **The frontend never reaches the backend's sources.** A `frontend-vue/` layer sits next to the backend, enters through `dms.frontend.ts`, lints with `antelopeNuxtConfig`, and tracks the pack's `build/backend-boundary.ts` so the build fails on an import of `src/`.
5. **Three agent files, fixed roles.** `AGENTS.md` is the hand-written repository part (what it is, versioning, tests) above the managed block. `ARCHITECTURE.md` at the root holds five sections in this order: runtime pieces, directory map (one line per `src/` folder), flows, tests, invariants. `CLAUDE.md` is `@AGENTS.md`. The managed block points to `ARCHITECTURE.md` when it exists (this release).
6. **Generated files say so in their name.** `*.generated.*` files are regenerated by a script `package.json` names, and the pack's ignore patterns leave them out of lint and format. Today the preset ignores only `**/i18n-registry.generated.ts`; cloud's `app-values.generated.ts` and dms's `eslint-globals.generated.*` are handled per repository.

## What agents stumble on today

- antelopejs: two `cli` folders (`src/cli`, 70 files, and `src/core/cli`, the bin) that depcruise treats as one module; the package depends on itself (`"@antelopejs/core": "link:."`); `host-module.ts` and `stub-interface.ts` are loaded by path and look dead; `test/` does not mirror `src/`; `.claude/skills/*` are text stubs on a Windows checkout.
- dms: `AGENTS.md` says two published packages and describes `pnpm run checks` as a build plus `check:backend`, while `release.yml` publishes three packages and `checks` is `antelopejs-checks`; two `e2e/`, two `checks/` and two `frontend-vue/` folders with different roles; `DMS_PREBUILT=1` runs a stale `dist`; a generated `blocks.json` and `mockup-spec.schema.json` CI diffs.
- cloud: a new `src/` folder that is not ranked; a component renamed in Vue but still named as a string from a page declaration (`check:dms-components`); `types:prepare` forgotten before lint; a module version bumped without its `antelope-lock/` entry; the vendored `app-values` files edited by hand.
